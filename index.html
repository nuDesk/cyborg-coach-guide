Cyborg Coach: learn by doing

Your first seven sessions

You do not need to learn everything before you start. Use one practical task to learn how to direct Claude Code, check its work, and turn what works into something you can reuse.

How to use this guide

Install Cyborg Coach once before you start. Five steps, then you are in Session 1. Install Cyborg Coach →

Want Claude to talk you through it? Copy full guide for an AI chat to give an ordinary chat the context. You still do the lessons in Code.

The coach teaches one small step at a time. Questions and detours are welcome — ask, then pick up where you left off.

After that, open the Code view in the Claude app, start a local session, and choose the folder you want to work in. Then paste one session's prompt. Every prompt below begins with /cyborg-coach:start on its own line, so a fresh session loads the coach before it reads the request; if the coach is already active where you are working, the prefix simply re-enters it. You do not need a separate invocation step.

The coach works where you work. It can read your conversation, and the files and tools that your Claude Code permissions and connected services make available — which is a matter of configuration, not a fixed one-folder boundary. It previews changes before writing, and you approve them. It will ask when it needs something it cannot observe. See Privacy and security.

These are learning sessions, not seven mandatory chats or calendar appointments. Continue the same session while it is useful. If you start a new one, bring your progress recap. Session 6 deliberately uses a genuinely fresh session to test continuity.

We assume Claude Desktop and Claude Code access already work. This guide is public; the plugin itself stays private and still needs an invitation to install. Use a practice folder and non-sensitive material. Review proposed changes before approving them; never paste credentials or confidential files. Stop whenever something is unclear. You can ask a question at any point and then return to the next step.

Install Cyborg Coach

Add Cyborg Coach to Claude, then start your first practice session. These instructions use the Mac app and assume Claude Code already works.

Want Claude to walk you through this?

Get Claude to Help You Install →

Having trouble? Go to Need help.

  1. Get access to the coach

    • Open the invitation email and accept it while signed in to the GitHub account it was sent to. You do not need a paid GitHub plan to accept the invitation.
    • No invitation? Ask whoever sent you this guide.
    • Open the repository: github.com/nuDesk/cyborg-coach

    You should seeThe Cyborg Coach files listed on that page. If the page is missing, check that you are signed in as the invited account and that the invitation was accepted.

  2. Make a practice session

    • In the Claude app, open Code, then New.
    • Select Local.
    • Open the folder dropdown next to Local and choose Open folder…
    • In the macOS chooser, go to Documents, click New Folder, name it Cyborg Coach Practice, click Create, then Open.
    • Check that this is the empty folder you just made, then click Trust workspace.

    You should seeAn empty message box, with Local and Cyborg Coach Practice selected.

  3. Tell Claude where to find the coach

    A marketplace is just an address Claude fetches the coach from. You add it once.

    • Next to the message box, click + (Add), then Plugins, then Browse plugins. Settings opens on Plugins → Discover.
    • At the top right, click Add, then Add marketplace.
    • Click the URL field and paste this address:
    https://github.com/nuDesk/cyborg-coach.git
    Then press ⌘C on Mac to copy it. Keep the .git ending.
    • Click the suggestion Use “https://github.com/nuDesk/cyborg-coach.git”, then Sync.

    You should seeA Cyborg Coach card appear.

  4. Install it

    • Click Add beside the Cyborg Coach card — not the Add at the top right.
    • Wait for the confirmation message.
    • Close Settings with the ✕ in the upper right.

    You should see“Cyborg Coach is installed and ready to use.” and the card reading Added.

  5. Start your first session

    • Back in the practice message box, type /cyborg-coach:start
    • Choose cyborg-coach:start from the dropdown. A highlighted start token appears in the box.
    • Click Send.

    You should seeA first reply offering four lanes and asking “Which one do you want?”

    Go straight to Session 1 and paste its prompt into that same message box — that prompt is your answer, and it starts the guided experience.

    Begin Session 1 →

    Installation is done on this Mac. You do not repeat it before each lesson.

Get Claude to help you install

An ordinary Claude chat can read what you paste and give you directions in plain language. It cannot see your screen, and it cannot install anything for you. Once the plugin is installed, you return to your local Code session to learn.

  1. Open a fresh ordinary Claude chat at claude.ai/new. This is regular Claude, not Code, and it needs no plugin.
  2. Give it this guide as context: open Copy full guide for an AI chat, copy the text, and paste it into that chat — but do not send it yet. Pasted text is the reliable default. You can also share the public guide address nudesk.github.io/cyborg-coach-guide if the chat confirms it can actually read that page. The plugin repository stays private; there is never a need to make it public.
  3. In the same unsent message, below the guide text, paste the prompt below, then click Send. Sending the guide on its own can trigger a summary or a run through every lesson; sending both together asks only for installation help.

If you get stuck, take a screenshot (Shift-Command-4 on a Mac) and crop or redact passwords, tokens, and anything personal or confidential before attaching it — or simply type the exact error text you see.

Need help

The repository page or Sync will not load

Being signed in to GitHub in a browser is not proof that Claude can fetch a private repository; the download uses the git credentials already on your computer. First check that you are signed in as the invited account and that the invitation was accepted. If it still fails, ask whoever sent this guide for a supported secure setup.

If a trusted GitHub sign-in prompt appears, complete it there; a sign-in prompt is not guaranteed to appear. Never paste a password or token into a chat or into a URL.

The /cyborg-coach:start command is not offered

Open a fresh Local practice session and type it again. If it is still missing, send whoever gave you this guide the step you are on and the exact message on screen — no secrets.

You have added the marketplace before

It is already listed under On this computer as nudesk-cyborg-coach. Skip to step 4.

The labels look different

Menu wording varies between versions. Some documentation says Add plugin where this guide says Browse plugins — follow what is on your screen. Official instructions: Install plugins (Desktop).

Updates and removal

Updates come from the same private repository through the native plugin surface. Automatic updating of a third-party marketplace is not guaranteed and may be off by default — see configure auto-updates. This package ships no custom updater. A new version may need a fresh session before it appears.

Use the native plugin management surface to disable or uninstall. Never delete your whole Claude configuration to remove a plugin. Removing it removes the four skills; the files you created live outside the plugin and stay yours. Revoking repository access stops future fetching but does not erase what is already downloaded.

Privacy and security

What nuDesk can see

Installing this plugin does not give Sean or nuDesk access to your conversations, your documents, or your work. The current plugin sends us no session data and no telemetry. Anything you choose to share — a screenshot, a note, a repository issue — is separate and voluntary.

What the coach can reach

The coach can read your conversation, plus the files and tools available to it under Claude Code's configured permissions and any services you have connected. Opening one project does not sandbox the coach to that folder; what is reachable depends on your settings. Installing it connects no email, Drive, or other account, and gives the publisher no access. Your existing integrations and your organization's controls still apply, and no plugin can override platform or administrator permissions. Review how Claude Code permissions work.

Where the work happens

With local Code, the work runs on your own computer, but the relevant prompts, context, and file content are sent to Anthropic for processing over encrypted connections — not everything stays on your laptop. Whether conversations may be used to improve models depends on your plan: Pro and Max follow your model-improvement setting; Team and Enterprise are not used for generative model training by default unless you opt in. Anthropic's Claude Code data usage policy describes retention and feedback exceptions; you can review your model-improvement preferences in Privacy settings.

Sensible habits

Start with non-sensitive material, read permission prompts instead of approving by reflex, redact screenshots before you attach them, and never share passwords or tokens. The coach adds no connections of its own and cannot bypass the controls you or your organization already have in place. Official guidance: Claude Code Desktop.

Desktop installation and startup were tested on an already-authenticated Mac. Invitation acceptance, first-time GitHub authentication, Windows, and the seven-session journey remain untested.

01

Get comfortable

Purpose: See the difference between Claude describing what it could do and actually doing a small piece of work.

Paste into the coach
/cyborg-coach:start Session 1: help me get comfortable, one small step at a time. Check my practice folder yourself, then propose one tiny file with its name and contents. Wait for my approval before creating it. Keep your replies short and teach me as we go.

Ready to continue

The coach looked at your practice folder, created only the file you approved, and you have opened it yourself. You know which file changed and how to undo that one change.

What you learned

You choose the scope and judge the result. A small successful test is evidence of that test — not a safety certification.

Technical note

Permission prompts vary with the selected mode and rules, so the presence or absence of one prompt is not a safety test. The coach will not guess which mode you are in; if it matters, check it yourself. Desktop permissions

02

Understand the building blocks

Purpose: Understand what belongs in settings, instructions, and reusable procedures before adding more configuration.

Paste into the coach
/cyborg-coach:start Session 2: teach me the building blocks using our practice file. Start with the difference between permissions and instructions, with one simple example. Pause before the next concept, keep replies short, and don't change my setup.

Ready to continue

You can distinguish permission controls, persistent guidance, and a repeatable procedure. You know why one project's facts should not fill the global instruction file.

What you learned

A project needs relevant context, not the largest possible instruction file. Our OS approach uses the global file as a small entrypoint to separately maintained knowledge. Instruction files add context; a link to another file does not prove it was read. Instruction and memory guidance.

03

Create your project-based agent

Purpose: Give Claude a clear job, relevant context, and a definition of success.

Paste into the coach
/cyborg-coach:start Session 3: help me set up a project for my own useful task. Start with one question about the result I want, unless we've already agreed it. Use the project starter, keep this standalone, and ask before writing. Guide one step at a time; stop after setup, before doing the task.

Ready to continue

The minimum setup checks required for this task pass. The project has substantive instructions and documentation, or suitable existing equivalents. Any remaining gaps are explicitly non-blocking for the scoped task; otherwise resolve them before proceeding. File creation alone is not a completed project or proof of OS readiness.

What you learned

A project-based agent is focused on a particular job. You do not need to build an organization-wide system to begin.

If you need a task

No use case yet? Try turning fictional workshop notes into a preparation checklist, keeping confirmed arrangements separate from open questions and leaving unknown owners or dates unknown.

04

Complete one useful task

Purpose: Produce something you can evaluate — not just a promising plan.

Paste into the coach
/cyborg-coach:start Session 4: help me complete the task we scoped. Reuse our agreed brief. Give me the next small step, do only the work I approve, then help me inspect the result one check at a time. Keep it local and draft-only.

Ready to continue

You have opened the output, assessed the agreed checks, and recorded any remaining limitation. An attractive answer is not enough.

What you learned

Good delegation includes review. Your corrections reveal what a reusable workflow needs to remember.

05

Turn the workflow into your own skill

Purpose: Capture a useful, repeatable procedure from the work you just checked.

Paste into the coach
/cyborg-coach:start Session 5: help me turn our checked workflow into a project-level skill. First, tell me which part seems worth repeating, or ask if that isn't clear. Guide one step at a time, check for an existing equivalent, and ask before writing. We'll test it on a different non-sensitive input.

Ready to continue

You have a project-owned skill, know how to invoke it, and have tested it on another input. If the procedure is not repeatable yet, record that and refine it rather than inventing a skill for the exercise.

What you learned

A skill captures how to do recurring work; the project supplies the context. The workshop example could become "prepare-workshop-checklist."

Your skill is not one of the packaged skills

This is your skill, separate from the package's four: /cyborg-coach:start, /cyborg-coach:starter-project, /cyborg-coach:starter-setup-check, and /cyborg-coach:starter-closeout. A menu listing does not prove a skill works, and neither does a plausible reply: proof is the session showing the skill actually invoked, plus a result you inspect.

Technical note

Project skills use a SKILL.md inside the project's .claude/skills/ folder; the coach can prepare it. Skills can be invoked directly or selected by Claude when relevant, depending on their configuration. We deliberately invoke this one for its first test. Official skills guide.

06

Close out and resume

Purpose: Make it possible to continue tomorrow without reconstructing today's conversation.

Paste into the coach
/cyborg-coach:start Session 6: help me close out with the closeout skill. Start by checking what changed and proposing the project notes to update; wait for approval before writing. Keep each reply short. Once those notes are saved, guide me through testing whether a new session can pick up where we stopped.

Ready to continue

A fresh local session can find the project's purpose, current state, and next action. If it cannot, correct the narrow documentation gap and check again.

What you learned

Closeout turns conversation into continuity. It is also where you notice lessons that might eventually benefit other projects.

07

Build your organizational OS

Purpose: Move from one working project to a foundation that supports several projects without mixing all their information together.

Paste into the coach
/cyborg-coach:start Session 7: help me build my organization's OS, starting with one shared procedure or lesson from our work. Begin with one question about what should carry across projects. Guide me one step at a time, keep private and project-only information separate, and ask before changing any files or global instructions.

Ready to continue

A fresh session in a second project locates and applies the approved organizational knowledge through the intended entrypoint. An OS brief or a set of folders alone does not meet that test. If something is blocked, keep the reviewed brief and the next action — do not mark the OS complete.

What you learned

The OS is the foundation for organizational knowledge and operating procedures across projects. It is directly informed by nuDesk OS's approach to scoped context, documented work, and deliberate learning — not a copy of its private implementation. One person's local reuse does not yet provide team sharing, synchronization, or administration.

Keep your place

If you pause or take a detour, paste this into the coach:

Paste into the coach
/cyborg-coach:start Give me a short recap I can bring back later: where we stopped, the useful result, what was checked, what remains untested, and one next action. Use only this conversation, my reports, and project records you actually read; distinguish them naturally where it matters. Omit private details. Don't restart onboarding when I return.

The guide supplies the sequence. The coach handles your questions. You do not need to memorize the framework; you will see it again as you do the work.
