Cyborg Coach

Learn by doing with a coach beside you.

Cyborg Coach helps non-technical knowledge workers get started with Claude Code and learn through four practical lanes—from completing useful work to building the foundation for an organizational operating system.

Start here

New here? Install Cyborg Coach. Already installed? Choose one of the four lanes below.

Install Cyborg Coach →Choose your lane →

How to use this guide

  1. In the Claude app, open Code, start a Local session, and choose the folder for your work.
  2. Once per new session, type /cyborg-coach:start, choose cyborg-coach:start from the dropdown, then click Send.
  3. Once the coach replies, it will help you execute your first task or set up a project on Claude Code.

Expect short replies and one question at a time. The coach explains as you go, checks what it can, and asks before making proposed changes. Start with non-sensitive material; never paste passwords or credentials. See Privacy and security.

Install Cyborg Coach

Add Cyborg Coach to Claude, then start on your own work. These instructions assume Claude Desktop and Claude Code access already work. This guide is public; the plugin itself stays private and still needs an invitation to install.

Get Claude to help you install

An ordinary Claude chat can read what you paste and give you directions in plain language. It cannot see your screen, and it cannot install anything for you. Once the plugin is installed, you return to your local Code session and start on your own work.

  1. Open a fresh ordinary Claude chat at claude.ai/new. This is regular Claude, not Code, and it needs no plugin.
  2. Give it this guide as context: open Copy full guide for an AI chat, copy the text, and paste it into that chat — but do not send it yet. Pasted text is the reliable default. You can also share the public guide address nudesk.github.io/cyborg-coach-guide if the chat confirms it can actually read that page. The plugin repository stays private; there is never a need to make it public.
  3. In the same unsent message, below the guide text, paste the prompt below, then click Send. Sending the guide on its own can trigger a summary or a run through every prompt; sending both together asks only for installation help.

If you get stuck, take a screenshot (Shift-Command-4 on a Mac) and crop or redact passwords, tokens, and anything personal or confidential before attaching it — or simply type the exact error text you see.

Need help

The repository page or Sync will not load

Being signed in to GitHub in a browser is not proof that Claude can fetch a private repository; the download uses the git credentials already on your computer. First check that you are signed in as the invited account and that the invitation was accepted. If it still fails, ask whoever sent this guide for a supported secure setup.

If a trusted GitHub sign-in prompt appears, complete it there; a sign-in prompt is not guaranteed to appear. Never paste a password or token into a chat or into a URL.

The /cyborg-coach:start command is not offered

Open a fresh Local practice session and type it again. If it is still missing, send whoever gave you this guide the step you are on and the exact message on screen — no secrets.

You have added the marketplace before

It is already listed under On this computer as nudesk-cyborg-coach. Skip to step 4.

The labels look different

Menu wording varies between versions. Some documentation says Add plugin where this guide says Browse plugins — follow what is on your screen. Official instructions: Install plugins (Desktop).

Updates and removal

Updates come from the same private repository through the native plugin surface. Automatic updating of a third-party marketplace is not guaranteed and may be off by default — see configure auto-updates. This package ships no custom updater. A new version may need a fresh session before it appears. The check-for-updates skill is a separate read-only check; it never installs an update.

Use the native plugin management surface to disable or uninstall. Never delete your whole Claude configuration to remove a plugin. Removing it removes the package’s ten skills and its packaged startup hook; disabling it turns both off for later sessions. The files you created live outside the plugin and stay yours. Revoking repository access stops future fetching but does not erase what is already downloaded.

How the coach starts

This Mac preview adds a small packaged startup hook intended for the macOS Desktop app. It loads static coaching guidance. The hook runs no background listener, reads no participant files, sends no telemetry, makes no network calls, and changes no files. Model context still goes to Anthropic, as explained in Privacy and security.

On Mac Desktop, automatic startup was observed. After a normal Quit and relaunch, the resume hook ran and the conversation continued; whether the guidance was freshly added again or simply retained from earlier context cannot be told apart. Automatic startup is not guaranteed, and Windows is not supported. Typing /cyborg-coach:start and choosing it from the dropdown remains the reliable way to begin.

Start on its own shows the four lanes; it never silently resumes a project. A specific request goes straight to that task.

Say “stop coaching” to stop optional suggestions in this conversation. Disabling the plugin in the native plugin settings is separate: it turns off the skills and the hook for later sessions.

Privacy and security

What nuDesk can see

Installing this plugin does not give Sean or nuDesk access to your conversations, your documents, or your work. The current plugin sends us no session data and no telemetry. Anything you choose to share — a screenshot, a note, a repository issue — is separate and voluntary.

What the coach can reach

The coach can read your conversation, plus the files and tools available to it under Claude Code's configured permissions and any services you have connected. Opening one project does not sandbox the coach to that folder; what is reachable depends on your settings. Installing it connects no email, Drive, or other account, and gives the publisher no access. Your existing integrations and your organization's controls still apply, and no plugin can override platform or administrator permissions. Review how Claude Code permissions work.

Where the work happens

With local Code, the work runs on your own computer, but the relevant prompts, context, and file content are sent to Anthropic for processing over encrypted connections — not everything stays on your laptop. Whether conversations may be used to improve models depends on your plan: Pro and Max follow your model-improvement setting; Team and Enterprise are not used for generative model training by default unless you opt in. Checked September 21, 2026 — for anything time-sensitive, defer to the official policy. Anthropic's Claude Code data usage policy describes retention and feedback exceptions; you can review your model-improvement preferences in Privacy settings.

The startup hook

In this Mac preview, a small startup hook adds the coach’s packaged guidance and the folder path where the plugin is installed to your Claude session context. That context is processed by Anthropic like the rest of your conversation. The hook does not read your files and sends no separate telemetry. Automatic startup is not guaranteed.

Sensible habits

Start with non-sensitive material, read permission prompts instead of approving by reflex, redact screenshots before you attach them, and never share passwords or tokens. The coach adds no connections of its own and cannot bypass the controls you or your organization already have in place. Official guidance: Claude Code Desktop.

Checked on an already-authenticated Mac: skill selection, the four-lane opening, useful tasks, OS setup and review, closeout, shared guidance in a fresh project session, automatic startup, and continuation after a normal Quit and relaunch. Not established: invitation acceptance, first-time GitHub authentication, loading a participant-created plugin, and copying from this page into other applications. Windows is not supported.

Lane

Create a Project-Based Agent

A project holds the context for several related tasks. For a client engagement, that might include preparing a kickoff, comparing options, tracking decisions, and drafting follow-ups. A meeting-prep procedure can become a skill; the client engagement is the project.

Kick off your first project

Tell the coach about the engagement or initiative—not just a task you repeat. It looks at what is already there and helps you choose a useful first task.

Paste into the coach
Help me set up a project.

Here is what happens next:

  1. Shape the work. If the idea is fuzzy, brainstorm with the coach. If you already know what you need, go straight to a short plan.
  2. Set up the shared context. The coach reuses existing documentation or proposes a project-level CLAUDE.md: instructions and context for this project. Your global CLAUDE.md is for guidance that applies more broadly; it is not changed as part of ordinary project setup.
  3. Do the first task. Approve the proposed setup and work together. The coach carries that approval into execution, shows the result, and performs the checks it can. You judge whether it is useful.

There is no required bundle of documents, and no need to paste another kickoff prompt if the agreed work is already underway. If you only want the project set up, say so.

While you work

Brainstorm the next task when you want help deciding what to do next. The coach uses what it already knows, asks one useful question at a time, and helps turn the idea into a plan. This is a conversation, not a required questionnaire.

Paste into the coach
Help me brainstorm the next useful task.

If email, calendar, or documents would help, ask about connecting your tools. You can keep working without a connection.

You may also get an occasional suggestion for a better approach or a useful tool. These observations come from the work in the session—not a background listener. You decide whether to use them.

When you stop

Closeout saves what changed, what remains open, and the next action. It is for stopping or handing off—not a compulsory step after every result.

Paste into the coach
I'm stopping here. Help me close out this session.

To return later:

  • Open a new Code → Local session in the same project folder.
  • Start cyborg-coach:start from the dropdown.
  • Ask the coach to pick up from the saved notes.
Paste into the coach
Help me pick up where I left off in this project.

You should recognize the project and next step from those notes. If not, tell the coach what is wrong. You do not need to leave a productive session just to run this check; try it when you return or when you specifically want to test resuming.

Two ways to ask

You can make a plain request, like the prompts above. Or type /cyborg-coach:session-closeout and choose the matching dropdown entry; that invokes the closeout skill directly. See What is a command?

Create a skill whenever it helps

Turn a useful procedure into a skill when you want to use it again. You can capture work you have done or design a new procedure. This is available at any point; you do not need to close out first.

Paste into the coach
Help me create a skill from what we just did.

Your project keeps the context; the skill describes how to do that procedure. The coach helps you invoke the skill and inspect its result, rather than treating a saved file as a successful test. If the app prevents creation or invocation, the coach explains what remains untested.

Lane

Build Your OS

Think of your OS as a shared home for your organization's ways of working: knowledge, procedures, skills, and approved lessons organized by role or division. Projects keep their own client facts and decisions; the OS holds what belongs across projects.

This foundation is directly informed by nuDesk OS—our operating procedures, written for code—not a copy of a private implementation. You can start here without first building a plugin or connecting GitHub.

Paste into the coach
Help me build my organization's OS.

Already have an OS?

Paste into the coach
Help me review and improve our OS.

How it works

  1. Document real workflows. Describe how the work actually gets done in conversation, or point the coach to selected existing documents.
  2. Review a source-backed blueprint. The coach proposes a structure that shows where each part came from. You approve, change, or reject it.
  3. Build and test the approved foundation. The coach sets up only what you approved, then checks that another project can find the right material without pulling in unrelated client information.

For an existing OS, the coach audits it against the same framework and proposes improvements. Nothing changes until you approve them.

A local folder is a starting point. Reusing it locally is not automatic team sharing; a shared repository or approved shared drive can help later, with deliberate access and update arrangements.

The coach’s skills

You normally ask in plain language after starting the coach. If you want to invoke one of the ten skills directly, type its command and choose the matching dropdown entry.

  • /cyborg-coach:start — begin coaching in this conversation; on its own it shows the four lanes.
  • /cyborg-coach:setup-project — set up or improve a project.
  • /cyborg-coach:setup-os — discover workflows, draft a blueprint, and set up or improve an approved OS.
  • /cyborg-coach:audit-os — assess an existing OS without changing it; repairs only after your approval.
  • /cyborg-coach:brainstorm — think through a project or next task.
  • /cyborg-coach:check-setup — inspect setup without changing it.
  • /cyborg-coach:check-for-updates — check coach versions without updating.
  • /cyborg-coach:session-closeout — save progress when stopping.
  • /cyborg-coach:create-skill — create and test your own procedure.
  • /cyborg-coach:create-plugin — package skills when useful.

For ideas, return to the four lanes in this guide or explore the Claude blog. For a specific technical question, ask the coach to check the relevant current official documentation.

Glossary and quick questions

Optional. Open an entry when a term gets in the way.

What is a skill?

A skill is a saved procedure Claude can use again—for example, preparing a meeting brief. It contains instructions and can include supporting references. A skill can be requested by name or selected when relevant; it is not a guarantee of a correct result. Skills documentation: https://code.claude.com/docs/en/skills

What is a command?

A slash command is a shortcut you invoke in Claude Code. For example, /cyborg-coach:session-closeout calls the coach's closeout skill. Asking in ordinary language is another way to request help. Not every slash command is a skill: some are built-in app actions. Claude's older custom-command format now works alongside skills. Skills and commands: https://code.claude.com/docs/en/skills

What is a hook?

A hook runs at a defined Claude Code event. This coach's packaged startup hook supplies a small, fixed piece of coaching guidance; it does not watch your activity in the background. It does not read participant files, change them or send data itself. Automatic startup has been observed on macOS Desktop but is not guaranteed; use Start when activation has not been confirmed. Hook documentation: https://code.claude.com/docs/en/hooks

What is CLAUDE.md?

It is a text file of instructions Claude Code can load: what the work is, where relevant material lives and how to approach it. Keep it useful and concise. It guides behavior; it does not enforce permissions or guarantee that Claude follows every rule. Instruction documentation: https://code.claude.com/docs/en/memory

Which instruction file belongs where?
  • User-level: ~/.claude/CLAUDE.md holds guidance relevant across your projects.
  • Project-level: CLAUDE.md or .claude/CLAUDE.md holds this project's shared guidance.
  • Nested: a subfolder can have guidance for work in that area.
  • Local personal: CLAUDE.local.md can hold unshared project preferences; exclude it from version control if used.
  • Managed: an organization may provide centrally managed guidance.

Several instruction files can load together; keep them consistent rather than assuming one automatically cancels another. You do not need all these files. Start with the project's actual needs. Scopes and loading: https://code.claude.com/docs/en/memory

Quick questions

Do I need to know how to code? No. Start with a useful result you can describe and judge. The coach helps with the steps; you still review the work.

Task, project or skill? A task is one piece of work. A project holds shared context across related work. A skill saves a reusable procedure, such as meeting preparation within a client project.

Do I need GitHub, connectors or my own plugin? Not for a first local task. Add one when it solves a real need. Your own plugin is optional packaging, not the organizational OS itself.

Does Start monitor everything? No. It starts coaching in this conversation. The packaged hook supplies static guidance on supported session events; neither is a separate observer of other sessions. Say “stop coaching” to stop optional suggestions here; disabling the plugin is a separate app action.

Can nuDesk see my session? Cyborg Coach does not provide nuDesk with session access or telemetry. Relevant conversation and tool context is processed by Anthropic; any services you connect have their own controls. Only use information you are authorized to share. Claude Code data usage: https://code.claude.com/docs/en/data-usage
